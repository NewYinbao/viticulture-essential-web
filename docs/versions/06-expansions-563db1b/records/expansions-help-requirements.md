# 扩展规则说明与新手引导适配（用户追加的必做需求）

此项属于本次 Tuscany EE、Moor、Rhine 实现的交付条件，不是后续可选优化。不做 World/Bordeaux/旧版额外模块。

## 功能与内容
1. 开局设置旁解释各模块的作用、推荐新手组合和合法搭配；明确 Rhine 替换而非混入本体/Moor。设置更改时规则摘要跟随更新，非房主也能看见；开局后不得改变规则。
2. 游戏内规则说明按服务器返回的本局配置展示：本体不被未启用扩展的说明干扰；标题、季节顺序、行动/奖励、工人、建筑、影响力地图和终局条件都按真实模块变化，不能只改标题。
3. Tuscany 分别解释四季与个人跨季流程、起床奖励、影响力地图/终局计分、特殊工人的训练费用及能力、建筑卡建造/使用/触发；具体金额、时机、上限以已核实官方规则和实际实现为准，不猜数。
4. Moor/Rhine 提供对应牌组简介、牌面中文效果、分支/数量/费用/使用条件、规则来源；引导当前决策所需信息，而不是为所有新牌套一个泛化提示。
5. 新手引导根据实际本局配置、本人回合和pendingChoice阶段给出下一步提示，定位/高亮真实可操作控件；说明为何暂时不能操作。多人响应只提示当前响应者可执行，不泄露其他玩家私有手牌。
6. 引导可开启、关闭、跳过、重新开始；使用清晰中文。保留原本体已有引导体验与纯本体开局路径。切房/重连/SSE/轮询不得残留旧模块的步骤、聚焦对象或高亮。
7. 手机与桌面均可阅读、操作；引导/规则面板不遮挡选牌/行动按钮，不抢占不合理焦点。键盘可达，打开关闭后焦点恢复，不出现不可见目标高亮。
8. 常用规则与引导文案随Go静态资源内嵌，本地无外网也可读；官方来源链接作为参考，不要求联网才能获取核心说明。复用现有 help.js、rules-content.js 等体系，避免另造脱节的规则副本。

## 验收
- 纯本体、各Tuscany模块独立开启、组合开启、EE+Moor、Rhine及Tuscany+Rhine的显示/隐藏与禁用组合一致。
- 实际HTTP公私View驱动，不能只伪造前端状态证明联动。
- 至少两名独立浏览器：房主改配置同步给访客、开局锁定；新增实际合法选择时规则入口与引导定位正确；断线/刷新恢复后仍正确。
- 截图检查桌面和手机viewport，检查不存在目标、溢出、遮挡；如果只跑了DOM测试而未看截图要明示。
- 原本体引导回归；Go与JS适用测试；更新扩展版内嵌二进制与发布文档，不能碰当前运行的dist/Viticulture.exe/3013公网服务/原存档。
- 未实现/未核实的模块不得由文案包装成可玩。总报告保留原功能未完成项；只有规则实现、界面、规则说明、新手引导均通过才能标记complete。

此文档仅为已加入的需求与验收清单，不代表实现已完成。
