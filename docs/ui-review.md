# 操作体验检查与改动

2026-09-11；实际使用 Chromium 检查桌面与 390×844 手机视口，保留原有酒庄配色及 SVG 插画。

| 观察到的问题 | 已做的修改 |
| --- | --- |
| 版本提示反复出现，行动区域被挤到下方 | 移除重复横幅；牌堆／家族默认折叠；范围说明集中在规则说明 |
| 手机上的手牌在整块庄园之后，需要长距离滚动 | 增加固定底部导航，桌面使用顶部吸附导航 |
| 各类手牌混排，找牌费时 | 按类型筛选并显示数量；待决选择自动恢复全部，避免隐藏可选牌 |
| 返回入口后恢复座位只能靠刷新 | 提供“回到上次的房间”按钮 |
| 第 2 格先被使用时，工人却画到第 1 格 | 按 seat.slot 匹配绘制；奖励格有标签；无限金币行动与私人轭分别显示 |
| 工人、轭或基本资源不足时仍可打开无效行动 | 在按钮中直接显示原因并禁用；服务器继续做完整规则验证 |
| 默认工人进不了已满的普通格 | 在可用时默认选择大工人；奖励默认值不再要求额外点选 |
| 拔藤选择与田地独立，易选错牌 | 轭的拔藤列表跟随田地，只列该田地上的藤 |
| 种植表单英文牌名、没有容量提示 | 中文牌名、已种数值／容量、缺失建筑提示；点击藤卡后显示对应田地卡 |
| 酿酒只分组，不知道结果／可酿几瓶 | 显示实时瓶数上限、酒种、预计品质及降级原因；提交前检查瓶数 |
| SSE 更新后旧行动面板还可提交 | 新 revision 到来关闭旧行动面板并提示；409 时拉取最新局面 |

确认按钮固定在棋盘内操作面板底部，窄屏也保持可达。真实浏览器验证了拔藤提交及桃红酒预览与服务器结果一致；没有仅以 DOM 模拟替代服务端操作。

## 试玩反馈后的提示优化

- 当前可选行动使用绿色边框和“可派遣”角标；不可用行动用虚线与“条件不足”。悬停行动时，对应类型手牌同步描边。
- 鼠标悬停、键盘聚焦或手机点按可显示简短原因。不可用按钮保留聚焦能力，但不会发送无效行动。
- 服务端只读计算金币、建筑、田地、工人、配方和部分访客分支的前置条件，不运行行动、不抽牌、不预测随机结果。前端补充当前字段所需资源的数量检查。
- 访客选项显示“可选／不可用”，默认选择可用分支；常见费用和收益直接写在短按钮标签内，长牌面与费用解释折叠。
- 手牌资源未选齐时禁用确认，旁边只显示一句所缺条件；选齐后显示“已就绪”。建造选项标记当前费用及缺少的金币／前置酒窖。

这些是必要条件和资源选择提示，最终仍由服务端校验具体组合；未把允许零收益的效果一律视为违法。新增测试覆盖原因气泡、键盘聚焦、费用不足的选项、资源数量与确认按钮的联动，同时验证提示不修改存档状态或泄露他人的手牌信息。

本地截图和测试报告位于 `artifacts/usability/`；属于测试产物，不提交到仓库。完整游戏测试和夹具测试分别记录，详见 [testing.md](testing.md)。

## 公共棋盘内的卡片操作面板

- 统一原来两套公共行动弹窗为 `action-panel.js`，在 `#board` 内展开，替换行动列表；起床奖励在 `#wake-panel` 内展开。移除全屏 dialog、背景遮罩和模糊样式。庄园与手牌可以直接查看、交互，不丢失当前选择。
- 工人、行动格、奖励、建筑、手牌、田地、葡萄和酒全部使用按钮卡片，无下拉菜单或隐藏 select。卡片以描边、勾选、虚线区分已选和条件不足；确认前仅保留一条简短状态。
- 建造展示全部八座建筑，包括已有设施。卡片显示本次费用和折扣；悬停或键盘聚焦显示作用、原价、当前费用、拥有状态和前置条件。改变行动格或放弃奖励，会重新计算费用和确认状态。
- 访客、订单与葡萄藤沿用手牌插画和中文牌名，详细牌面放在悬浮说明中。订单再点酒卡；种植再点田地卡，并检查多张藤合计容量。
- 酿酒先选酒瓶，再点葡萄分配；预览保留当前酒瓶编号，显示酒种、品质和酒窖降级。悬浮说明限制在面板边界内。
- 面板顶部保留自己的金币、胜利分、待命工人；手机使用内部滚动、固定确认区和“查看庄园／当前行动”往返导航。Esc、取消和返回均不提交；SSE 新 revision 或 409 会清理旧选择。

验证：扩展 `usability-test.cjs`，使用隔离存档和真实服务器验证八座建筑状态／折扣、建筑扣费、访客牌 ID、订单交付、收获、双藤同田种植、拔藤、桃红酒与起床奖励；检查桌面／390px 面板范围、气泡边界、庄园可交互、取消无请求和过期局面清理。截图见 `artifacts/usability/desktop-building-panel.png`、`mobile-building-panel.png`、`mobile-visitor-cards.png`。


## 种植条件检查、规则速查与新手模式

- 在自己的行动回合，种植入口即使缺藤、缺设施、田地已满或没有工人，仍能以“查看条件”打开。其他回合和未完成的选择继续遵守派工限制。
- 藤卡同时列出全部设施与容量条件；点击不能种的藤会定位到检查区域，显示棚架／灌溉是否已有、藤的容量占用、三块田地的实际空余容量和出售状态。检查不选择无效藤、不发送行动；没有手牌时提示去葡萄藤市场。
- 导航栏与入口增加“规则／规则说明”和“新手引导”。规则按入门、四季、工人、种植、收获、酿酒、订单访客、建筑八个主题组织；每次只展开一个主题，说明内附出版方手册和 FAQ 入口。规则文字以本仓库已核对的 EE 手册、FAQ 和实际版本范围为依据，详细边界仍见 rules-review.md。
- 新手模式默认关闭，偏好及导览进度仅保存在当前浏览器。四步认识界面后切换到随局提示；提示考虑季节、当前回合、待决选择和已有资源，手动定位相关控件。行动面板内另有一句短提示与相关规则入口；可随时关闭或重看导览。
- 规则说明使用普通页面区域，不遮罩、不锁住其他控件。查看规则、切换模式保留行动草稿；从行动面板打开规则时，Esc 先关闭规则，再按一次才关闭行动。

验证新增三组真实浏览器场景：不可种藤的完整缺项和只读检查、四步导览／键盘／偏好保存与规则往返、390px 布局和 SSE／回合／待决选择的提示切换。累计 14 组体验检查；相关截图为 `desktop-plant-conditions.png`、`mobile-plant-conditions.png`、`desktop-rules.png`、`mobile-rules.png`、`mobile-beginner-guide.png`。
